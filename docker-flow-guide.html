Docker & Docker Compose Visual Guide

Bản đồ trực quan giải thích cặn kẽ flow hoạt động của Docker, Docker Compose và sự khác biệt mấu chốt giữa môi trường Development (Dev) và Production (Prod).

🧩 4 Khái Niệm Nền Tảng Cốt Lõi

Mọi hoạt động trong Docker đều xoay quanh vòng tuần hoàn 4 thành phần sau:

1. Dockerfile (Công thức): File văn bản chứa các chỉ thị từng bước (cài OS, cài runtime, copy code, lệnh khởi chạy).
2. Image (Bản đóng gói tĩnh): Kết quả sau khi docker build. Image là Read-Only, không bao giờ thay đổi sau khi tạo.
3. Container (Thực thể sống): Bản thể đang chạy được sinh ra từ Image. Một Image có thể khởi chạy nhiều container giống hệt nhau.
4. Registry (Kho lưu trữ): Nơi lưu và chia sẻ Image (như Docker Hub, AWS ECR, GitHub Packages).
💾 Volume & Network (Mở Rộng Sức Mạnh)
⚠️ Đặc tính Ephemeral (Tạm thời) của Container
Container sinh ra và chết đi rất nhanh. Mặc định mọi file sinh ra trong container sẽ biến mất vĩnh viễn khi container bị xóa!
  • Volume / Bind Mount: Gắn ổ đĩa máy host vào container. Giúp dữ liệu Database tồn tại vĩnh viễn, hoặc giúp Container đọc code sống trực tiếp từ máy Dev.
  • Network: Tạo mạng LAN ảo nội bộ. Các container có thể "nói chuyện" với nhau trực tiếp qua tên định danh (DNS nội bộ) thay vì phải gán IP tĩnh.

🐙 Docker Compose: Nhạc Trưởng Cho Ứng Dụng Đa Dịch Vụ

Nếu không có Docker Compose, một dự án gồm Next.js + Spring Boot API + Postgres sẽ bắt bạn phải gõ hàng chục câu lệnh docker run -p ... -v ... --network ... cực kỳ dễ nhầm lẫn. Docker Compose gom toàn bộ cấu hình vào 1 file docker-compose.yml duy nhất.

📄 Ví dụ file docker-compose.yml
services:
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DB_HOST=db
    depends_on:
      - db

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD: secretpassword
    volumes:
      - db_data:/var/lib/postgresql/data

volumes:
  db_data:
⚡ Các Lệnh "Thần Thánh" Hàng Ngày
  • docker compose up -d: Bật toàn bộ dịch vụ dưới nền (Background).
  • docker compose down: Tắt toàn bộ hệ thống sạch sẽ.
  • docker compose down -v: Tắt và xóa luôn cả database volume (làm mới hoàn toàn).
  • docker compose logs -f web: Theo dõi log trực tiếp của dịch vụ web.
  • docker compose exec web sh: Mở terminal bên trong container để debug.
  • docker compose restart backend: Khởi động lại riêng 1 service.

🛠️ Cấu hình Compose chuẩn cho Dev:

services:
  web:
    build: 
      context: .
      dockerfile: Dockerfile.dev
    ports:
      - "3000:3000"
    volumes:
      # 1. Mount code từ máy thật vào container:
      - .:/app
      # 2. KHÔNG ghi đè node_modules của container bằng máy host:
      - /app/node_modules
    command: bun dev
✅ Khi nào KHÔNG cần build lại?
  • Sửa file .tsx, .css, .js, .json.
  • Thêm ảnh, font, asset mới vào thư mục public/.
  • Đồng nghiệp git pull code mới về máy.
⚠️ Khi nào BẮT BUỘC phải build lại ở Dev?
  • Cài thêm thư viện mới (sửa package.json) ➔ Chạy docker compose build hoặc docker compose up --build.
  • Thay đổi nội dung file Dockerfile.
🚀 Luồng Hoạt Động Ở Môi Trường PRODUCTION (Triển Khai Thật)

Mục tiêu: Ổn định, bảo mật cao nhất, hiệu năng tối đa. Tất cả code đã được nén và đóng băng vĩnh viễn (Immutable Image). Server không bao giờ cài Git, không clone code, không mount ổ đĩa máy host!

🏭 Dockerfile Multi-Stage Tối Ưu Cho Prod:

# GIAI ĐOẠN 1: BUILD CHUẨN BỊ
FROM oven/bun:latest AS builder
WORKDIR /app
COPY package.json bun.lockb ./
RUN bun install --frozen-lockfile
COPY . .
RUN bun run build   # Đóng gói HTML/CSS/JS nén gọn

# GIAI ĐOẠN 2: CHẠY PRODUCTION SIÊU NHẸ
FROM oven/bun:alpine AS runner
WORKDIR /app
# Chỉ copy thành phẩm đã build, bỏ qua toàn bộ source thừa
COPY --from=builder /app/.next ./.next
COPY --from=builder /app/public ./public
COPY --from=builder /app/package.json ./package.json

EXPOSE 3000
CMD ["bun", "start"]
🛡️ Tại sao Prod KHÔNG ĐƯỢC dùng Bind Mount?
  • Tính nhất quán tuyệt đối (Hermetic Build): Đảm bảo hình ảnh được test ở CI chạy giống 100% khi lên server thật.
  • Bảo mật: Nếu server bị tấn công vào container, hacker không thể ghi đè làm thay đổi file mã nguồn trên máy chủ host.
  • Khả năng Scale ngang: Khi có hàng triệu người dùng, ta có thể scale ra 10 server khác nhau chỉ bằng việc kéo cùng 1 Docker Image về chạy.
⚖️ Bảng So Sánh Toàn Diện: DEV vs PROD

Bảng tổng kết giúp bạn và team đưa ra quyết định kiến trúc chính xác cho từng môi trường:

Tiêu chí 💻 Môi Trường DEV (Lập trình) 🚀 Môi Trường PROD (Triển khai thật)
Cơ chế nạp Code Bind Mount (volumes: - .:/app) COPY thẳng vào Image (Bake vĩnh viễn)
Khi Dev sửa code Tự động nhận ngay qua Hot-Reload Bắt buộc phải build lại Image mới
Khi `git pull` code mới Tự động nhận ngay (do folder đã mount) CI/CD build ra Image mới rồi mới deploy
Lệnh chạy chính bun dev / next dev (Có Turbopack, source map) bun start / next start (Đã minified, tối ưu tốc độ)
Dung lượng Image Có thể lớn (chứa đầy đủ tool debug, node_modules dev) Siêu nhỏ gọn (Chỉ giữ lại artifact build, dùng Alpine)
Bảo mật & Cách ly Thấp (cho phép chỉnh sửa trực tiếp) Cực cao (Read-only filesystem, chạy quyền non-root)
💡 Tóm Tắt Trong 1 Phút (Mental Model)
Khi làm việc hàng ngày (Dev):

Cứ code thoải mái, pull code thoải mái. Đừng bận tâm về việc build image! Chỉ khi nào thêm thư viện mới (package.json) hoặc đổi cấu hình cổng/Dockerfile thì mới cần gõ docker compose up --build.

Khi phát hành sản phẩm (Prod):

Mỗi bản cập nhật là một "chiếc hộp sắt kín" hoàn toàn mới mang số hiệu phiên bản riêng (tag). Không bao giờ vào server sửa code dạo trực tiếp!
